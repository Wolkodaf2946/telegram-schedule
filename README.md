# Расписание Сириуса — Telegram-бот

Бот показывает расписание групп Университета «Сириус» с
[schedule.siriusuniversity.ru](https://schedule.siriusuniversity.ru/list): на сегодня, на завтра
или на любой день через календарь из кнопок. Каждый пользователь выбирает свою группу.
Расписание по расписанию же (по умолчанию в 06:00 МСК) загружается с сайта в PostgreSQL,
и бот отвечает из базы, не дёргая сайт на каждый запрос.

## Возможности

- `/start` — приветствие; новому пользователю — просьба выбрать группу.
- 👥 **Группа** — напишите часть названия (`ИОП-ИТ`, `ББ-25`), бот найдёт группы на сайте.
  Новую группу бот загружает сразу, дальше она обновляется вместе с остальными.
- 📅 **Сегодня / ➡️ Завтра** — пары с номером, временем, типом (цвета как на сайте),
  аудиторией, преподавателями и «окнами» между парами.
- ◀ ▶ под расписанием — листать дни; сообщение редактируется, а не плодится.
- 📆 **Календарь** — месяц кнопками: цифра — есть пары, точка — свободно, `[6]` — сегодня.
- При запуске бот пишет администраторам «Бот запущен» со статусом данных.

## Доступ к боту

По умолчанию (`ACCESS_MODE=open`) бот открыт для всех. Чтобы пускать только избранных:

```
ADMIN_IDS=<ваш Telegram ID>     # узнать у @userinfobot
ACCESS_MODE=approval
ALLOWED_USER_IDS=111,222        # необязательно: кого пустить сразу, без заявки
```

Дальше новый пользователь жмёт /start и видит «заявка отправлена», а вам приходит карточка
(имя, @ник, ID, язык) с кнопками **✅ Разрешить / ❌ Отклонить**. Решение сразу сообщается
пользователю.

### Админ-панель

`/admin` или кнопка **🛠 Админ-панель** (видна только администраторам):

- вкладки **⏳ Заявки / ✅ Активные / ⛔ Баны** со счётчиками;
- по 8 человек на странице, «‹ Назад / Вперёд ›»; у каждого — быстрые кнопки:
  в заявках ✅ принять и ❌ отклонить, у активных ⛔ забанить, у забаненных ✅ разбанить;
- нажатие на имя открывает карточку: ник, ID, язык, группа, когда впервые пришёл и когда был
  активен;
- администратора забанить нельзя (👑), бан работает и в открытом режиме.

Панель — одно сообщение, которое редактируется на месте. Каждое нажатие — два коротких
запроса к БД по индексу (страница через `LIMIT/OFFSET` и счётчики), сколько бы ни было
пользователей. `/refresh` — обновить расписание с сайта прямо сейчас.

В открытом режиме о каждом новом пользователе вам тоже приходит уведомление (без кнопок).
Все такие события пишутся в отдельный журнал `logs/users.log`.

## Быстрый старт

```bash
cp .env.example .env      # заполнить TELEGRAM_TOKEN, POSTGRES_PASSWORD (и DATABASE_URL), ADMIN_IDS
docker compose up -d --build
docker compose logs -f bot
```

Серверу нужен доступ к двум адресам:

- **schedule.siriusuniversity.ru** — из-за рубежа может не открываться; тогда `HTTPS_PROXY`.
- **api.telegram.org** — из России может быть недоступен; тогда `TELEGRAM_PROXY`
  (действует только на Telegram) или `TELEGRAM_API_URL`. Пока Telegram недоступен, бот не падает:
  повторяет подключение и продолжает обновлять расписание, в логе — `cannot reach telegram bot api`.

Без Docker: поднять PostgreSQL, указать `DATABASE_URL` в `.env`, затем `make run`.

## Настройки

Все настройки — переменные окружения, полный список с комментариями в [.env.example](.env.example).
Главное:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SYNC_TIMES` | `06:00` | Когда обновлять: `06:00,14:30`; `off` — только вручную |
| `TIMEZONE` | `Europe/Moscow` | Пояс для «сегодня» и `SYNC_TIMES` |
| `SYNC_ON_START` | `true` | Обновить при старте, если данные старше суток |
| `SYNC_MONTHS_AHEAD` | `1` | Сколько месяцев вперёд загружать |
| `ACCESS_MODE` | `open` | `open` — для всех, `approval` — по заявкам |
| `ADMIN_IDS` | — | Администраторы: заявки, уведомления, команды |
| `ALLOWED_USER_IDS` | — | В режиме `approval` — доступ без заявки |

Разовая загрузка без бота (например, из системного cron): `make sync` или `bot -sync-once`.

## Логи и отладка

- Консоль — читаемый текст (`docker compose logs -f bot`).
- `logs/bot.log` — JSON с ротацией. Каждый апдейт пишется строкой `update handled` с
  `update_id`, `user_id`, `chat_id`, текстом/кнопкой и длительностью; ошибки внутри обработчика
  несут те же поля.
- `logs/users.log` — журнал пользователей: `new user` (id, ник, имя, фамилия, язык, статус) и
  `access changed` (кто из администраторов и какое решение принял).
- `logs/dumps/` — если сайт ответил чем-то, что парсер не понял, здесь сохраняется сырой ответ
  и описание запроса. По нему можно починить парсер, не воспроизводя ошибку.
- `make errors` — последние ошибки и предупреждения из лога.
- `LOG_LEVEL=debug` — дополнительно каждый запрос к сайту (путь, статус, размер, время).

## Скорость

Кнопки и «Сегодня/Завтра» читают только базу (миллисекунды). Почти всё время ответа — это
запросы к Telegram, поэтому бот делает их минимум: одно сообщение на команду, ответ на кнопку
параллельно с редактированием, соединения с Telegram переиспользуются (HTTP/2, долгий keep-alive).
Поиск группы кешируется на час и идёт в «тёплой» сессии сайта (~40 КБ вместо ~590 КБ).

Если ответы всё равно медленные, смотрите `duration_ms` в строках `update handled` в
`logs/bot.log`: при прокси до Telegram это в основном его задержка — проверить можно так:
`curl -x <прокси> -o /dev/null -w '%{time_total}\n' https://api.telegram.org`.
